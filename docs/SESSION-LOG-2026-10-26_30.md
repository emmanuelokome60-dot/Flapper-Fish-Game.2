## 7. APK build failed — out of memory (28–29 Oct)

Two errors, one cause. `System.OutOfMemoryException` in the Unity CIL Linker, and
`LLVM ERROR: out of memory` in clang++. Host memory, not a project bug.

| | |
|---|---|
| RAM | 31.7 GB |
| Page file | manually capped 4–8 GB (`AutomaticManagedPagefile: False`) |
| Commit limit | 36.7 GB |
| Commit in use, Editor closed | 31.2 GB |
| Logical cores | 12 |

Windows makes every process *reserve* against commit limit = RAM + page file, up
front. IL2CPP spawns one clang++ per core; twelve jobs reserving a couple of GB each
are refused. Nothing to do with disk speed or swapping.

Demand-side settings changed with the Editor closed, backup in
`Backups/20261028_projectsettings_il2cpp_memory/`:

| File | Key | Now |
|---|---|---|
| `ProjectSettings.asset` | `AndroidCreateSymbols` | 0 (Disabled) |
| `ProjectSettings.asset` | `il2cppCodeGeneration` | `{Android: 1}` (size) |
| `UnityConnectSettings.asset` | `m_EngineDiagnosticsEnabled` | 0 |

Engine diagnostics forces debug symbols on, which is what put `-g` in the clang
command line. Turning it off removes the reason symbols were there.

`AndroidCreateSymbols` and its `Disabled/Public/Debugging` enum were verified by byte
search against `UnityEditor.Android.Extensions.dll`. The key was absent from the asset,
so a guessed name would have been a silent no-op.

**Still outstanding.** The page file is the root cause and is still capped. A reboot
happened 28 Oct 18:45 but the setting was never changed.
`sysdm.cpl` → Advanced → Performance Settings → Advanced → Virtual memory Change →
tick "Automatically manage" → reboot.

## Findings

- **The scene had never been fully reverted.** A previous session's revert stopped
  halfway, leaving `waterDrag: 0.2`. The real baseline was far worse than any doc said.
  → A tuned number in a doc is not a number in the scene. Check the scene.
- **Rise-in-hops, fall-like-a-stone *is* Flappy Bird.** Three earlier tuning rounds all
  changed the rise and never touched the fall. All three had an identical hop and differed
  only in how hard they punished a miss. The fix was the fall, not the tap.
- **The surge mechanic was effectively off.** `push = (Surge−1) × currentPush` produced
  0.23 units of shove against a 1.09-unit fish — a fifth of a body width. Invisible.
- **`.claude/` held 25 MB of stale git worktrees.** `git log HEAD..<worktree>` returned
  0 commits; `main` was 7 ahead. Nothing to keep. Gitignored.
- **Figma: `resize()` resets `textAutoResize` to FIXED.** Silently left all 227 text
  boxes at their 10px placeholder height. Sizing mode must be set *after* resize.
- **Validation against collapsed geometry proves nothing.** The first "0 overlaps" pass
  measured 10px-tall boxes. After the height fix, three real collisions surfaced.
- **Exact-match text replacement correctly refuses hand-edited nodes.** Three Figma
  texts had been edited by hand; the script skipped them rather than clobbering them.
  Read each, kept the added meaning, applied by node ID.
- **A build OOM is a machine fact, not a code fact.** Two different tools in two
  different languages both died allocating. Check
  `(Get-CimInstance Win32_ComputerSystem).AutomaticManagedPagefile` before opening a
  single project setting. Project settings only reduce demand; they cannot raise a
  ceiling the OS refuses to raise.
- **A serialized key that is absent from the asset is not a key you can guess.**
  `AndroidCreateSymbols` had never been written, so there was no example to copy.
  Verified the name and enum against Unity's own DLLs. A wrong name writes cleanly,
  changes nothing, and looks fixed.
- **Checked whether the pause row ever shows two buttons before hard-coding three.**
  Every `ShowRunButtons` caller is show-all-three or hide-all, so fixed positions are
  safe and a `HorizontalLayoutGroup` would have bought nothing — and would have
  swallowed the corner-anchored `SoundButton`, needing a `LayoutElement` to escape.
- **A Unity class rename is a `.meta` move, not a scene edit.** The scene links
  components by the GUID in the `.cs.meta`, never by class name. Keep the meta with
  the file and the scene needs no change at all. The obvious route — rename the
  file, then fix the scene YAML — is both more work and more dangerous.
- **`Assembly-CSharp.csproj` lists every source by filename.** It is Unity-generated,
  so immediately after a rename `dotnet build` fails with `CS2001: Source file …
  could not be found` before compiling anything. Patch the `<Compile Include>` line
  and rerun; the csproj is gitignored and Unity regenerates it on next open.
- **A readability score can land under target and still be right.** The README
  measured grade 2.4 against a 4–5 target. Flesch–Kincaid punishes short punchy
  lines, and the longest sentences were still 19–22 words. Padding sentences to
  raise the number would have made the page worse, not better.
- **The cave was getting brighter with depth, not darker.** `ApplyCaveDepth` lerps
  *toward* `deepLight`, so `deepLight` must be **lower** than `startLight` or the
  lamp brightens as you dive. `deepLight` went 0.02 → 0.12 between 22 and 26 Oct and
  inverted the whole effect; git history found the last good values. Restored to 0.02.
  The Light2D's own serialized `m_Intensity` does nothing at run time — line 769
  overwrites it every frame — so it is only worth setting to match `startLight`, which
  is what keeps the Scene view honest before Play.
- **The paid fish was never a missing asset, it was a miscount.** The agenda had slot 6
  down as "add a 6th art asset / make fish 5 the paid one / hide slot 6" — three
  options, all of them work. The real answer was to delete one card and change nothing
  else, because the card count *is* the rule: `(1 << (n-1)) - 1`.
- **The card and skin arrays matched by picture, not by filename.** PEIXE5 is FISH3;
  PEIXE3 is FISH4. Trusting the numbers would have produced a confident reorder that
  broke a pairing which was already correct. Opening the two PNGs settled it in seconds
  and removed the entire reordering step from the job.
- **A versioned save key needs every reader versioned with it.** Bumping `OWNED_KEY` in
  `FishInventory` alone would have left the Tools menu clearing the old name, so the one
  tool for testing the change would have quietly stopped working — while still printing
  a success message.

## Standing rules confirmed this session

- Never patch scene YAML with the Unity Editor open. Inspector edits instead.
- The saved scene beats a script default. Changing a `[SerializeField]` default moves nothing.
