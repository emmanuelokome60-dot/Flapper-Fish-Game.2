## Part 1 — The Canvas (2026-10-09)

### §1 Four groups instead of one pile

Everything on the Canvas sat in one flat list, so a button could not be moved for one screen
without moving it for every screen. Grouped into four children, each owning what only it shows:

```
Canvas
  HUD              Distance, Coin Counter, PauseButton   (full-screen stretch)
  MainMenu         OverLay, Play, Characters, Title, Sound
  GameOverMenu     Divider, StatRow, "Game Over", Restart, Home
  Pause Buttons    Restart, Home, Resume, Sound
```

Done as document-level YAML surgery — parsing `--- !u!<classid> &<fileID>` blocks rather than
running a regex over the whole file. A regex matches the right text in the wrong document; the
parser cannot. All 15 GameManager slots verified resolving afterwards.

### §2 Game over got its own Restart and Home

The complaint was that moving the game-over buttons also moved the paused ones, because they were
the same two objects. The fix is duplication, not cleverness: `GameOverMenu` now carries its own
pair, composed to sit with the score rows, and the pause pair stays where it was. Two screens,
two positions, no shared state.

### §3 The pause buttons soft-locked the game

`Pause Buttons` was saved **inactive**. `SetActive(true)` on a child of an inactive parent is a
silent no-op, so pausing showed nothing and there was no way back out. General rule from it:

> A group is either **container-toggled** (set the parent, leave children alone) or
> **children-toggled** (parent always on). Mixing the two is what hangs.

### §4 Two objects called HomeButton

One of them was actually named `'HomeButton '` — trailing space. Unity single-quotes any name with
surrounding whitespace, which is the only reason it was visible at all. I had read my own padded
output and claimed the rename was done; `cat -A` on the raw line proved otherwise. The scene parser
grew a `yaml_name()` unquoting helper so a trailing space can never pass for a match again.

## Part 2 — The pause screen

### §5 The dim went blurry

Freezing the game behind a flat dim looked cheap, so the frozen frame is now captured and softened:
render the camera to a RenderTexture, then halve it bilinearly `pauseBlurSteps` times with
`Graphics.Blit`. Each halving is a free 2×2 box blur done by the sampler — no shader, no
post-processing stack.

Two things had to be learned the hard way:

- **24 depth bits, not 0.** Unity 6's Render Graph refuses to render a camera into a target whose
  Depth Stencil Format is None.
- **`RenderTextureFormat.RGB565`.** The camera clears to alpha 0, bilinear halving smears that
  alpha outward, and `RawImage` multiplies by it — so the HUD ghosted through as dark smudges at
  5 or 6 steps. A format with no alpha channel samples as fully opaque and the ghost cannot exist.
  Fixing the format fixed every overlay element, not just the distance text that was reported.

### §6 The stat row

Coins, score and best score needed equal gaps and equal screen padding. A `HorizontalLayoutGroup`
with `childForceExpandWidth: 0` and `childControlWidth: 1` does all of it; TMP already implements
`ILayoutElement`, so no `ContentSizeFitter` was needed.

The rows looked vertically out of step, and the obvious suspect was the coin icon. It was not —
all three TMP labels were set to `V = Top`, so each one hung from a different ascent. The icon was
innocent.

### §7 A line that tapers

Wanted: a divider thin at both ends, thicker in the middle. Generated `DividerTaper.png`, 512×16,
white with a sine-shaped alpha so one sprite carries the shape:

```
halfThickness(x) = (H/2 - 0.5) * sin(pi * x / (W-1))
alpha(x, y)      = clamp(halfThickness(x) - |y - centre| + 0.5, 0, 1)
```

### §8 Sound on/off

Two buttons, bottom-left of the main menu and the pause screen, sharing one state. The whole mute
mechanism is `AudioListener.volume = Muted ? 0f : 1f` plus a sprite swap and a `PlayerPrefs` key —
no mixer, no audio manager, and there were no sounds in the game yet. The pause copy lives in the
same group as the run buttons, so it has to be toggled with them or it stays on screen all run.

## Part 3 — The cave goes dark

### §9 Depth, not time

Darkness ramps on **distance travelled**, lerping a Global Light 2D from `startLight` to
`deepLight` across `darkestAtDistance`. There is no surface in this game — the fish lives in the
cave and the run only ever goes further in — so the first naming (`surfaceLight` / `abyssLight`)
was wrong and was corrected.

`CaveDepth` is set **before** the null check on the light, so the lure still tracks depth even
with no light wired.

### §10 The lure

A Light 2D on `Player_Fish` with `SpotLight2D.cs`, flaring on each swim. `PlayerControllerScript`
exposes `SwamThisFrame`, a frame-flag set only where the fish really swims — so the light inherits
every existing guard for free: no flicker while dead, paused, on the menu, or when the tap hit a
UI button.

**The bug I put there:** making the flare depth-aware, I changed a bounded
`current = baseIntensity + pulseBoost` into `current += pulseBoost`. Tapping is the one input a
player can spam without limit, and mashing reached **9× the intended peak** — enough to take the
darkness out of the game entirely. Clamped with `Mathf.Min(current + pulseBoost, peak)` and proved
by simulation: 1.25 against a 1.30 ceiling clamped, 11.7 unclamped.

### §11 `caveLight` was pointing at the lure

Both are `Light2D`, so the slot accepted the wrong one without complaint: `ApplyCaveDepth()` drove
the lure with the cave curve while `SpotLight2D` wrote the same field every frame, and the cave
never darkened at all. Found twice.

### §12 Lower intensity is not the lever

Asked whether the light should go up or down for an eerie cave, the answer was neither on its own:
**contrast sells darkness.** A uniformly dim screen reads as muddy, the eye adapts to it in
seconds, and on a phone outdoors it just disappears. Global light down, lure up, and the gap
between them is the effect.

Underneath the mood there is a fairness floor, measured from the scene rather than guessed:

| | |
|---|---|
| Rock speed | 3.5 u/s at the start, 8 u/s by 90 s, 10.4 u/s mid-surge |
| Fish to the right edge | 11.85 units |
| Lure reach then | 3.63 units → **0.45 s** warning at 8 u/s, **0.35 s** in a surge |

0.35 s is under what tap-to-swim can answer — reaction alone is ~0.25 s and the fish still has to
travel. So at full speed the lure **cannot** be the only light; the player has to read rock
silhouettes against the background. The global light is a fairness mechanism, not atmosphere.

Also found, and nobody designed it: darkness ramps on distance and speed ramps on time, and at the
values of the day the two peaked within seconds of each other — hardest lighting stacked on
hardest speed. Pulled apart by raising `darkestAtDistance`.

### §13 "Too dark and muddy" was arithmetic

Two multiplicative darkeners had been stacked, and the background is the one thing hit by both:

```
menu : light 0.30 x tint 0.45 = 0.135      2.2x darker than the 0.30 that was tuned
deep : light 0.16 x tint 0.45 = 0.072      nearly black
```

Everything collapsed into one near-black band — low *contrast*, not low brightness. Recommended
0.75 on the tint. (It was later set by eye to `0.706, 0.638, 0.638` — slightly warm, a touch
under.)

## Traps this session re-proved

- **A script's class name and file name must agree**, or the component comes back as a missing
  script on the next reimport. `SpotLight2D.cs` was holding `class LightTapPulse`. Renamed back to
  `SpotLight2D` by request — **both** halves, since reverting the file name alone would have
  restored the exact mismatch. Keep the `.cs.meta` with it; the GUID is the scene's only link.
- **A rename is two edits that are only correct together.** Mid-rename the `mv` was declined,
  leaving `LightTapPulse.cs` holding `class SpotLight2D` — broken in a *new* way. Stopping between
  the two is worse than either end state.
- **`Assembly-CSharp.csproj` goes stale after a script rename** and the offline
  `dotnet build` check fails on a path that no longer exists. Corrected in place, twice.
- **Back up before editing, not after.** `GameManager.cs` was edited while git was 101 lines
  behind. The backup had to be *reconstructed* from the edits rather than copied, and is labelled
  that way in the DEVLOG table.
- **A doc that quotes a tuned number goes stale the next time the number moves.** Which is why the
  warning at the top of this file exists.
