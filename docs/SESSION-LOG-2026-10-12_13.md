## Part 1 — The fish shop (2026-10-12)

The Characters screen existed but **nothing in the buying path had ever run**. By the end of the
day a purchase worked end to end and survived a relaunch.

### §1 Button art was swapped

`buyArt` and `equippedArt` pointed at each other's sprites, so every locked card read **EQUIPPED**
and the one you owned read **BUY**. Fixed in the scene. The files have since been renamed
`Buy.png` / `Equipped.png` / `Select Button.png`; `verify_scene.py` now pins all three **by GUID**,
so the swap cannot come back unnoticed.

### §2 The price lived in two places

`PEIXE BLOQUEADO.png` had a coin icon and `300` painted into it, while `FishInventory.price` was a
separate 300 in the Inspector. Nothing kept them in step.

Resolved as **code owns the number**:

- Removed the painted coin and digits from the PNG, rebuilding the dark bar from a clean column so
  the rounded ends, lock icon, silhouette and "Unlock with:" survived untouched.
- Added a `PriceText` label inside each block, written by `Refresh()` from the serialized `price`,
  measured onto the centre of the now-empty bar — pos (−3, −99), later rescaled.

### §3 Buying failed silently

Short of coins, the button did nothing and the player could not tell a broken button from an empty
wallet. Used Unity's **own** disabled state rather than hand-tinting: the buttons were already
ColorTint with a disabled colour set, so `buttons[i].interactable` greys the badge *and* blocks the
dead click. No new art, no colour maths.

### §4 The wallet

Two separate faults:

- `WalletText` was never wired. Created it at the screen's top-left and pointed `walletText` at it.
- **`ShowCoins()` was writing `Coins` — this run's haul, which resets to 0 every run — instead of
  `TotalCoins`, the saved wallet.** That is why the balance never looked cumulative. This was the
  real "wallet is broken" bug.

Later gave it the same coin icon as the run counter by making `GameManager.BuildCoinIcon` take a
target and a size, rather than writing a second copy that could drift.

### Design: five free fish, one to buy

Reversed twice before settling, and the history matters:

1. Originally `Load()` forced `ownedMask |= 1` — fish 0 was free and always equipped.
2. Briefly made **everything** locked, which surfaced the forced bit as the reason resetting
   `FishOwned` appeared to do nothing.
3. Settled on **`PEIXE1`–`PEIXE5` free, a sixth block costing 300**, so a new player can swap skins
   immediately and saves toward one aspirational fish.

The rule is derived, not hardcoded:

```csharp
if (cardArt.Length > 1) ownedMask |= (1 << (cardArt.Length - 1)) - 1;
```

Add a block and it automatically becomes the new one to buy. The `> 1` guard is not paranoia — at
length 0 the shift count goes negative and C# masks it to 5 bits, so `1 << -1` becomes `1 << 31`.

**Open gap:** there is no `PEIXE6.png`. `Refresh()` falls back to `lockedArt` when `fishArt` has no
entry for an index, so the sixth card still shows the silhouette **after it is bought** — the
purchase registers and the badge changes, the picture does not. Drop in a `PEIXE6.png` as
`fishArt[5]` and it completes itself with no code change.

## Part 3 — Gameplay feel (2026-10-13)

### The flashing vertical seam

A thin line swept across the background with the scroll, blinking in and out.

**Cause:** `ScrollObject.Update()` nudged *each copy* along by its own
`position += left * speed * deltaTime`, and recycled with a *relative* jump. Nothing ever rebuilt a
position from an exact source, so two copies at different magnitudes did not preserve their spacing
in float, and every wrap added another rounding error. The gap drifted off `width`, and **the error
compounded the longer a run went** — which is why it looked intermittent.

**Fix:** X is now derived every frame from a clock all copies share —
`Mathf.Repeat((Time.time - startTime) * scrollSpeed, span)` — instead of accumulated. `scrollSpeed`
and `startTime` are taken from the first copy, like `width` already was; `startTime` *had* to be
shared, because clones can get their `Start` a frame later and a per-copy start time would have
baked that frame in as a permanent gap.

### Surge audit

Traced the whole chain. **The surge maths was correct** — sine arch derived from `elapsed`, one
shared `SpeedMultiplier` so rocks, trash and coins cannot desync, correct reset on run start and
game over, and a self-limiting push on the fish that caps at `push / currentReturn`.

Measured and rejected two changes I was ready to make: tunnelling is impossible (0.208 units per
step at max surge against a 1.09-unit collider, so Discrete detection is right), and
`Interpolate: None` is correct because `FixedUpdate` writes `transform.rotation` directly.

Two real problems found beside it:

- **Statics survived Play sessions.** `EnterPlayModeOptions: 3` disables both domain and scene
  reload, and nothing reset statics, so `Surge` and `SpeedMultiplier` carried over — stop Play
  mid-surge and the next session began mid-swell. Added a
  `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` guard, which runs before the first scene
  loads regardless of reload settings.
- **The fish's Rigidbody2D Inspector values were dead.** The scene stored `Gravity Scale 2` /
  `Linear Damping 0` while `PlayerController.Awake()` overwrote both with 1.2 / 2. Someone had
  tuned the rigidbody and seen no effect. Set the scene to match; zero behaviour change, but the
  Inspector stops lying.

### Surges now scale with depth

`Surge()` takes the existing `progress` and ramps its amplitude:

```csharp
float strength = Mathf.Lerp(1f + (surgeStrength - 1f) * SURGE_AT_START, surgeStrength, progress);
```

Debris came along **for free** — `ObstacleDrift` already multiplies each piece's push by `Surge`,
so a deeper current carries trash faster with no second number to keep in step.

`SURGE_AT_START` is `0.5f` — half strength at the surface, full at depth. First attempt lerped from
`1.0`, which made the opening minute completely glassy (`push = (Surge − 1) × currentPush` is zero
at strength 1). It is a **const, not a serialized field**: a new `[SerializeField]` on a component
already saved in the scene comes back as **0**, and 0 here silently restores the glassy opening.

| Depth | Peak surge | Fish push | Fish drift | Debris push |
|---|---|---|---|---|
| 0s | ×1.150 | 0.45 u/s | 0.11 u | 1.38 u/s |
| 30s | ×1.200 | 0.60 u/s | 0.15 u | 1.44 u/s |
| 90s+ | ×1.300 | 0.90 u/s | 0.23 u | 1.56 u/s |

### The cave was too wide

Simulated the real `SpawnRock` maths against the five actual rock sprites rather than guessing.
Median gap was **5.62 units (5.2× the fish)**, with 7-unit openings that had nothing to thread.

| Field | Was | Now | Why |
|---|---|---|---|
| Min Gap | 3.5 | **3.0** | Tightest squeeze 3.54 → 3.08 |
| Min Depth | 1 | **2.5** | Kills the sliver rocks that caused the wide outliers |
| Max Depth Change | 1.5 | **1.0** | Smoother walls |
| Max Width | 8 | **10** | The two biggest rocks were being scaled *down* to fit 8 |

Result: median **3.98** (3.7× fish), widest 5.83 → **4.78**.

Three findings worth keeping:

- **`Min Scale` is inert.** Identical results at 0.39 and 0.55 — with `minDepth` at 2.5 every rock
  is already scaled above that floor, so the clamp never fires.
- **Do not raise `Min Depth` past 3.** It reverses, because `allowed = budget − minDepth` starts
  capping how deep a row may go. At 3.5 the median gets *wider* again.
- **Raising `Max Width` made walls smoother, not rougher** — jaggedness dropped 0.51 → 0.37,
  because rocks reach their asked-for depth instead of being cut short by the width clamp.

## Two lessons that cost real time

### 1. Unity's PlayerPrefs cache

Most of 2026-10-12 was lost to this. The registry read `FishOwned=0, Coins=854` while the game was
being handed `FishOwned=7, Coins=554`. Every reset appeared to do nothing.

**The Editor reads PlayerPrefs into memory once per session and serves that copy.** An external
registry write is invisible to the running game and is overwritten when Unity quits. Quitting first
is *not* a reliable workaround — it was tried and still drifted.

Fixed by building **`Tools → Fish Shop`** (`Assets/Editor/FishShopDebug.cs`), which goes through
`PlayerPrefs` itself so the two cannot disagree: *Reset Skins*, *Set Coins to 0 / 100 / 854*,
*Show Save State*. Every item refuses to run during Play — `GameManager` caches the wallet in a C#
field at `Awake`, so a mid-Play write is ignored and then overwritten. Editor-only, so it cannot
ship.

What finally cracked it: one temporary `Debug.Log` of the in-memory values. `Debug.Log` writes to
`Editor.log`, which can be read directly without the user copying anything.

### 2. The Inspector lies, repeatedly

Three separate instances of a saved value silently overriding or contradicting the code:

- Rigidbody2D gravity/damping overwritten by `Awake` (scene said 2/0, game ran 1.2/2).
- `ObstacleSpawner.minDepth` — script default 2, scene 1. **The scene always wins**, so editing a
  script default does nothing.
- The fish's start position: the scene transform is −5.65, but `ResetPlayer(PlayerStart())` moves
  it to **−2.96** on PLAY. Measuring the swim-in from the scene transform gave 4.08 s; the real answer
  is 3.32 s.
